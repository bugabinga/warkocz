# Implementation evidence

`SPEC.html` remains the binding completion contract, unchanged by this implementation.
Version remains `0.0.0`; this is not a usable Git client or a 1.0 release candidate.

## Implemented internal core

| Source | Behavior | Explicit limits |
| :--- | :--- | :--- |
| `src/bytes.zig` | Caller-buffer exact edits; validates ranges, ordering, capacity, aliases before writing; BOM/UTF-8/raw newline inspection; exact line spans. | No editor storage selection, encoding conversion, metadata handling, or persistence. |
| `src/engine/text_merge.zig` | Unchanged, one-sided, identical, and independent single-contiguous-range composition; exact source ranges and origin; ambiguous/overlapping edits remain conflicts. | Not general multi-hunk diff3, structural merge, Git strategy equivalence, or binary preview. |
| `src/session.zig` | Separate immutable inputs with SHA-256 identities; explicit unresolved/review state; manual choices/composition; exact edits; reset; full-state bounded undo/redo; monotonically versioned mutations. | Single-file, in-memory only; whole-result history copies; synchronous input hashing must not run on latency-sensitive UI paths. |
| `src/engine/snapshots.zig` | Caller-owned slot/worker/lease tables; generation/token ABA protection; exact active-lease result checks; cancellation retains readers; confirmed death permits reclamation. | No process, IPC, shared-memory payload, locking, or OS death detection; caller serializes ownership. |
| `src/vcs/paths.zig` | Target-specific lexical path checks with exact rejection spans; Windows device aliases and UTF-8 validity; POSIX byte preservation. | Lexical validity is not filesystem safety; collision, normalization, symlink, namespace, permissions, and length checks remain. |
| `src/invocation.zig`, `src/main.zig` | Literal argv parsing, explicit paths/labels, help/version, controlled argument exhaustion, refusal of unavailable operations. | No diff/merge executor, window, wait implementation, output save, or Git registration. |

All core backing storage is caller-owned; these modules do not allocate heap storage.
Fixture capacities are not approved application resource budgets.
Core ownership assumes no concurrent mutation of borrowed buffers.
Result editing does not implicitly resolve a conflict; explicit in-memory resolution is separate from durable save/completion, which is unimplemented.
Use Both records ordered byte composition, not semantic correctness.

## Blocking decisions and environment evidence

- Foreign native integrations need exact proposed revisions, licenses, compatibility evidence, and approval before adoption.
- Numeric pools/queues/undo/worker/LSP/GPU caps need measurement and owner approval; test buffers do not settle them.
- Required owner review of themes/typography/workflows cannot be replaced with an agent assertion.
- Cold startup requires an approved verified cache-reset API; no cache reset or reboot was attempted.
- WSL distributions are installed, but WSLg is not native Ubuntu Wayland/X11 acceptance and no GUI evidence was collected.
- No native macOS ARM64 environment is established by the current host or cross-build.
- Missing implementation is still work, not acceptance evidence; none of these gates authorizes relaxing `SPEC.html`.

## Invocation behavior today

`--help` and `--version` return information only.
Valid `diff`/`merge` requests return exit 1 with `FeatureUnavailable` before opening files.
Malformed requests return exit 1 with a specific parser error and no path-content logging.
Argument conversion uses a bootstrap-only 4096-byte arena, including metadata and platform-dependent conversion buffers.
Exhaustion returns exit 1 with `ArgumentCapacityExceeded` and a size-reduction diagnostic, not a successful operation.
Closing a future window must not be interpreted as success; no window or durable-completion path exists yet.
