Scope

Provide a full daily/advanced Git client combining editable two-way comparison, common-ancestor three-way merge, structural diff/merge, syntax presentation, and result-workspace LSP. Unsupported capabilities must degrade visibly to lossless text. The user judges behavioral correctness; the application does not prove program equivalence.

  • Required platforms: Windows 11 x64; Ubuntu 24.04-class Linux x64, both Wayland and X11; macOS 14 ARM64. Other architectures are best effort.
  • Core UI, engines, grammars, and highlighting are bundled and work offline without an IDE, Node/Python runtime, or developer toolchain. Installed Git may be required; detect its version/compatibility without changing global config.
  • Initial delivery requires compatible GPU/driver support. Graphics initialization failure produces a native actionable error without opening or mutating repositories. A software renderer is not required.
  • Project-owned code is MIT; required dependencies must have compatible open-source redistribution terms and notices.

Not required: full IDE, full jj client, AI-generated resolutions, cloud services/accounts, telemetry, collaboration, editable hex/image merge, or historical-revision LSP workspaces.

Diff & merge

  • Two-way mode takes explicit inputs and writable destination. Three-way mode keeps base, both inputs, and editable result logically distinct, regardless of pane count. Source inputs remain read-only unless separately selected as writable destinations.
  • Provide structural moved/reordered/edited-element views alongside exact text, word, and character views. Structural merge must demonstrate capability comparable to Mergiraf on reviewed representative fixtures.
  • Text-clean and successful structural resolutions may be accepted automatically. Retain immutable input identities, original conflict, engine/version, resolution origin, final result, and reviewed/unreviewed status.
  • Allow manual result editing, choosing either side/base/both where meaningful, resetting decisions, and revisiting automatic resolutions. Use Both is composition, not a correctness verdict.
  • Support multi-file sessions with searchable file/conflict navigation, filters, unresolved counts, progress, and recovery. Label inputs by actual operation/ref roles, including rebase, rather than unexplained ours/theirs.
  • Malformed source, unsupported grammar, parser/engine failure, timeout, and resource limits expose exact degraded capability and preserve user decisions.
  • Multiple merge bases and strategy-specific Git cases require faithful handling or explicit Git fallback. Do not invent a single base or infer resolved state solely from conflict-marker scanning.

File fidelity

  • Preserve bytes outside intentional edits, encoding, BOM, mixed CRLF/LF, final-newline state, comments, whitespace, and relevant metadata. Formatting, normalization, and encoding conversion are explicit actions, never incidental save effects.
  • Whitespace/comment hiding and collapsed regions affect presentation only; hidden evidence remains revealable and preserved. Textconv output and shaped text are review views, not writable source.
  • Detect binary/image content; provide safe previews where possible and explicit whole-side selection without destructive text conversion.
  • Handle rename/delete, rename/rename, directory/file, symlink, executable-bit, and submodule conflicts explicitly through faithful backend support or Git fallback.
  • Before mutation, detect case/Unicode collisions, reserved or unrepresentable paths, and platform filename restrictions. Report exact affected paths and a safe decision path.

Language intelligence

  • Provide structural parsing and editor-quality syntax presentation. Expose highlighting, structural diff, structural merge, and LSP as separate per-language capabilities.
  • Result-workspace LSP provides hover, definition navigation, references, symbols, and diagnostics with project paths/dependencies/config and synchronized unsaved edits. Version requests; discard stale replies. Diagnostics are advisory.
  • Historical inputs are syntax/structure-only. Language services initialize asynchronously; missing/crashed servers and partially valid results do not gate basic reading/editing.
  • Discover configured servers; installing language packs requires explicit consent with version, provenance, license, and capability information. Support user-defined grammar, extension/shebang, highlighting, engine, and server registrations under workspace trust controls.
  • Engine interfaces expose structured changes/conflicts and source ranges, not only ANSI output. Capability-based engine choice must not imply universal language support.

Acceptance matrix: Java, Kotlin, JavaScript, TypeScript, Rust, Lua, Zig, Nushell, JSON, YAML, TOML; C, C++, C#, Go, Python; HTML, XML, CSS, Markdown; custom packs.

Every listed language requires rendering/editing, exact preservation, truthful capability declarations, and explicit unsupported-case fallback. Representative languages must demonstrate each structural/LSP feature in complete multi-file projects, including embedded-language boundaries, syntax errors, and missing-server degradation. First structural fixtures target Zig and JSON; this does not reduce the complete matrix.

Interface & actions

  • Use a modern, minimal-chrome, result-centered adaptive layout with selectable base-to-input/result comparisons, expandable context, synchronized panes, optional four-version overview, and persistent pane/layout preferences. Prioritize reading changes and resolving conflicts over toolbars, borders, and decorative panels; keep essential actions discoverable.
  • Default to JetBrains Mono with a bundled Nerd Fonts icon fallback. Use the icon fallback for icon glyphs, not ordinary code text; icons retain accessible names and must not be the sole explanation of unfamiliar actions. Initially fonts are bundled only, with licensed coverage/fallback; family selection is within that bundle.
  • Typography must be state-of-the-art, legible, and crisp. Choose a coherent size/weight/line-height hierarchy by workflow importance: result code and active conflicts receive primary reading space, file/navigation headings establish orientation, and secondary metadata is quieter but never tiny or low-contrast. Keep comparison panes at matching code sizes; adapt to DPI, window size, and user zoom rather than shrinking primary content to fit chrome. Preserve configurable font sizes, optional ligatures, accurate caret/selection alignment, Unicode/graphemes, tabs, long lines, wrapping/scrolling, and IME.
  • Default to Nugu dark/light themes, following system appearance with manual override. Preserve Nugu semantic palette roles and contrast policy across syntax/diff/conflict/focus/diagnostics. Provide accessible labels, screen-reader semantics, visible keyboard focus, and meaning without color alone.
  • Make the product fun and lovable through thoughtful details, friendly concise language, satisfying feedback, and a consistent visual personality. Delight must not distract from risky merge decisions, obscure errors, delay input, or weaken confirmations; any nonessential motion respects reduced-motion preferences.
  • Ctrl+P opens universal fuzzy action search from every normal context, including on macOS. Every action has name, aliases, help, binding, availability, and disabled reason; help is visible before execution.
  • Palette, menus, mouse, keys, and context help share one action model and safety checks. No primary workflow requires a terminal or undocumented chord.
  • Custom modal navigation/editing has visible mode, mnemonic discovery, full remapping, and key-conflict diagnostics. Preserve ordinary selection/editing, clipboard, undo/redo, mouse parity, and IME composition; no required Vim diff keymap.
  • Keep hidden regions, formatting-only changes, base visibility, stale results, and unresolved decisions discoverable.

State, recovery & cancellation

  • One application-state owner applies versioned worker results. Detect external file/index/HEAD/operation changes; serialize mutations sharing Git common-directory resources and coordinate locks across worktrees.
  • Atomically save results after checking current input/index/HEAD/operation state. External edits and stale drafts require deliberate reconciliation; never overwrite newer state silently.
  • Persist recoverable encrypted drafts and decision provenance, with session undo/redo and immutable input identities/hashes. Healthy storage permits ≤1 second crash loss while dirty; explicit save/completion requires durable flush. Persistence failures visibly invalidate the guarantee.
  • Opening/editing a result never automatically stages, commits, pushes, or continues the parent operation. Failed save/hook execution remains failed/unresolved.
  • Expose progress/state and cancellation for long work; reject stale results after input/view changes. A mutation crossing an atomic boundary must finish or roll back that step before acknowledging cancellation.
  • Cancellation preserves inputs and existing repository state or reports precisely which atomic steps completed and their recovery path. Distinguish editor undo, crash recovery, reflog recovery, and irreversible remote effects.

Trust & privacy

  • Untrusted repositories remain inspectable without executing repository-provided hooks, LSP/build discovery, plugins, or config-driven commands. Execution requires explicit revocable trust identifying repository and scope; grants cannot silently expand to other worktrees/repos or changed executable config.
  • No silent content upload, telemetry, cloud analysis, package installation, or code execution merely to render a comparison. Network use is explicit for remotes or approved retrieval; local inspection/comparison/merging works offline.
  • Prevent secret/content leakage through logs, errors, clipboard side effects, indexes, caches, and recovery records. Sensitive durable drafts use protected per-user storage, encryption with protected keys, and retention/deletion controls.
  • Credentials/signing use configured system/Git mechanisms, not plaintext application token stores. Isolate trust contexts and validate traversal/symlinks, rendered content, and plugin/server boundaries.
  • Do not auto-load repository fonts. The selected shaper's untrusted-font warning must be respected; initially only bundled fonts are accepted.

External invocation

  • Provide standalone file diff/merge and Git difftool/mergetool contracts: explicit paths/labels, writable result, blocking/wait behavior, and documented exit statuses.
  • Success requires durable output and explicitly completed resolution; closing a window is not success.
  • Handle spaces, quotes, non-ASCII, leading dashes, and native separators without shell interpolation vulnerabilities.
  • Git registration is documented or explicitly opt-in; launch never modifies Git configuration.
  • jj integration is optional only where a small adapter reuses contracts and faithfully preserves its operation/conflict representation, including explicit handling or rejection of multi-sided conflicts.

Zig-owned application/UI/editor and structural diff/merge algorithms; native rendering, no browser/webview. Foreign dependencies require justified, licensed, approved integration. Candidate investigation does not establish final adoption or compliance.

  • Immediate UI descriptions use fixed frame scratch; stable IDs, focus, and editor state are retained. Bound traversal/draw work, sleep while idle, update accessibility incrementally.
  • Compare bounded piece tree and rope for edit/undo, line/offset lookup, snapshot cost, byte preservation, and exhaustion before selecting text storage.
  • Structural engines/parsers execute in lazy bounded worker processes. Shared-memory-first transport uses bounded versioned control messages, read-only input snapshots, separate result buffers, cancellation, and stale-result rejection.

  • Reuse compatible permissive implementation source and documented algorithms with provenance. GPL reference engines serve differential comparison, not copied/translated MIT implementation code.

kb is not paragraph layout, IME, rasterization, font discovery, or accessibility. Its unsupported explicit bidi controls remain an acceptance gap. Library allocator hooks alone do not establish safe bounded operation.

Build, CI & delivery

  • mise owns the development-tool registry and exact pinned versions. Minimal mise tasks delegate to authoritative Zig build steps for compilation/tests/benchmarks/packaging; foreign build tools sit behind Zig adapters. Local and CI use the same registry/steps.
  • Track latest stable through reviewed upgrade PRs and committed tool/dependency revisions, integrity metadata, and artifact hashes. Acceptance builds never resolve floating latest versions. A compatible complete toolchain graph must be demonstrated; byte-identical reproducibility is not assumed.
  • GitHub Actions PR gates cover formatting/static checks, unit/property tests, focused integration, and platform launch/input. Nightly gates cover full large-tier/fault matrices; release requires complete acceptance and controlled-hardware benchmark evidence.
  • Untrusted contributions cannot reach release secrets or personal-machine runners. Authoritative benchmarks use explicitly approved local jobs, no persistent runner installation; hosted timing alone is not authoritative.
  • Portable-first packages: Windows archive, Linux relocatable bundle, macOS app bundle. Sensitive state remains protected per-user, not plaintext beside executables.
  • Manual download/replacement only initially, with documented state migration/failure/rollback behavior; no background update checks.
  • Publish versioned artifacts, checksums, verifiable provenance, dependency/font notices, and explicit unsigned-package labels. OS signing is deferred.

Coding discipline is maintained in src/AGENTS.md, not duplicated here. Conditional dependency, benchmark, and delivery procedures live in local agent skills.
